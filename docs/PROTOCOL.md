# Протокол Ambilight 1

Локальная сеть IPv4. ПК отправляет только RGB-цвета светодиодов, изображения экрана не передаются. Контроллер работает независимо от интерфейса хаба.

Обнаружение: UDP broadcast 19446, `ALDISC1 <16 hex nonce>`. Ответ на исходный адрес/порт: `AL1|<nonce>|<12 hex chip id>|<firmware version>`. ПК сверяет nonce, идентификатор и локальный адрес. Устройство со старым адресом ищется по сохранённому ID.

Первичная привязка: физическое удержание кнопки 5 секунд открывает защищённую паролем точку доступа и шестизначный код на 5 минут. Пароль AP создан случайно и доступен через USB Serial 115200. Код показан на локальной странице AP 192.168.4.1. POST /pair, form `code`, возвращает token и закрывает код. HTTP /status и /control требуют Bearer token. Только доверенная локальная сеть: HTTP не шифрует метаданные и обмен при привязке. Доступ из интернета не предусмотрен. Настройка Wi-Fi доступна только через интерфейс AP.

POST /control: form power (0/1), brightness (0–100), nightBrightness (0–100), count (4–360), session (uint32). Изменения NVS записываются после 1,2 секунды покоя. GET /status: id, version, power, brightness, nightBrightness, count, streaming, rmtReady.

Кадры UDP 19447: magic ALF1 (4 байта), session uint32 LE, sequence uint32 LE, count uint16 LE, 2 резервных байта (0), затем count × RGB8, затем HMAC-SHA256 по заголовку и RGB с ASCII token в качестве ключа. Максимум 1128 байт для 360 LED. ESP32 отклоняет неподписанные, повторные и относящиеся к другой сессии кадры. Яркость применяется контроллером после RGB, физическое выключение имеет приоритет над кадрами. Цвета в предпросмотре учитывают яркость, но не являются подтверждением доставки UDP.

Через 3,5 секунды после прекращения валидных кадров свет выключается. Последующее включение кнопкой без ПК даёт постоянный тёплый цвет (255,143,49) с nightBrightness. Физическая кнопка переключает сохранённое power. Энкодер изменяет текущую яркость; в автономном режиме — nightBrightness. Программа опрашивает состояние раз в секунду и сохраняет физические изменения в конфигурации.

События от worker: отсутствуют, интерфейс опрашивает status. Методы: init, status, settings, layout, calibrate, preview, overlay, scan, pair, autostart. `overlay {enabled, depth, monitor}` показывает на выбранном мониторе полосы реального захвата (1–30% глубины) и не блокирует работу; `enabled:false` скрывает их. Поиск неблокирующий, результат в status. Калибровка ограничена 5 секундами, UI продлевает её, только пока открыт соответствующий раздел. EOF останавливает рабочий процесс.
